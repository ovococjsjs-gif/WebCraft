# Сохранения мира · `voxel-lab/world`, формат 6

Сборка 0.8.0 · 26 сентября 2026. Нормативные типы: `packages/core/src/persistence.ts`; проверка и миграции: `packages/storage/src/format.ts`. Это собственный формат, не `level.dat` Minecraft.

## Принципы

1. Сохраняются игровые данные, а не меши, световые кеши или GPU-ресурсы. Изменения блоков воспроизводятся поверх **того же генератора**, с которым создан мир.
2. Основная копия, резервная копия и ревизия каталога заменяются в одной транзакции IndexedDB. Сравнение ревизий защищает от перезаписи другой вкладкой.
3. Ошибка квоты, прерванной транзакции или повреждения файла не сообщается как успешная запись. Файл с неизвестным форматом/генератором не угадывается.
4. Ручное сохранение всегда захватывает новый снимок. Автосохранение может пропустить чистый мир.
5. Подтверждение записи относится **к моменту захвата**. Если между захватом и завершением IndexedDB что-то изменилось, мир остаётся грязным.

## Конверт и контрольная сумма

```json
{
  "format": "voxel-lab/world",
  "version": 6,
  "checksum": { "algorithm": "SHA-256", "value": "64 hex symbols" },
  "payload": { "name": "…", "createdAt": 0, "savedAt": 0, "core": {}, "client": {} }
}
```

SHA-256 вычисляется над каноническим JSON `payload`: ключи объектов отсортированы, порядок массивов сохранён, `undefined`-поля объектов не сериализуются. Глубина ограничена 64 уровнями. Для импорта **сначала** проверяется сумма исходного payload, **затем** его версия и поля нормализуются. Нельзя добавлять новые поля и после этого сравнивать старую сумму.

Миграция возвращает конверт версии 6 с `migrated: true` и новой суммой. Повторное чтение этого конверта должно пройти проверку. Импорт создаёт отдельную запись, не заменяя оригинальный мир.

## Совместимость

| Формат | Источник настоящей фикстуры         | Особенности миграции                                       |
| ------ | ----------------------------------- | ---------------------------------------------------------- |
| 1      | автономный 0.2                      | девять блоков хотбара становятся предметами                |
| 2      | автономный 0.3                      | добавляются выживание, время, существа и снаряды           |
| 3      | только синтетическая схема в тестах | добавляются системы блоков и станции                       |
| 4      | автономные 0.4, 0.5, 0.6            | добавляются измерения и боссы                              |
| 5      | автономный 0.7                      | метаданные экземпляров, режим, прогресс и состояние победы |
| 6      | текущий                             | чтение без понижения/смены версии генератора               |

Настоящие файлы в `fixtures/saves/` экспортированы через интерфейс сохранённых HTML. Отдельного релиза-экспортёра формата 3 в полученном архиве нет; синтетический тест не выдаётся за исторический golden-файл.

Генераторы 1–4 читаются, но номер не переписывается. Генератор 1 допустим для `flat` и `valley`, не для биомных миров. Новый мир использует 4. Генератор 2 не получает крепостей генератора 3; исправленные внешние города Края и проходы крепостей Нижнего мира включаются только для 4. Файлы версии 6 не предназначены для старых сборок.

## Предметы и метаданные

Слот — `null` либо `[itemKey, count, damage, enchantments?]`.

- `count` проверяется по максимальному размеру стека конкретного предмета, а не всегда по 64.
- `damage` — целое от 0 до `itemDurability(item) - 1`. У недолговечных предметов — 0. Используется единая долговечность инструментов, брони, щитов и луков.
- `enchantments` — ограниченная карта идентификаторов и уровней. Поддержаны `efficiency`, `sharpness`, `fortune`, `unbreaking`, `protection`, `power`, `feather_falling`; максимумы заданы в `item-metadata.ts`.
- Стеки объединяются только при совпадении предмета, износа **и** зачарований.
- Выпавший предмет: `[itemKey, count, damage, x, y, z, age, enchantments?]`.

Глобальная карта старых зачарований распределяется по уже существующим подходящим предметам инвентаря, контейнеров и выпавших предметов, включая неактивные измерения. После миграции карта пуста: новый предмет того же типа автоматически не улучшается.

Сетка крафта не восстанавливает открытый интерфейс. Захват складывает её в **копию** инвентаря. Остатки при полном инвентаре становятся предметами на земле в снимке; живая сетка не меняется. Курсор сохраняется отдельным слотом. На переходе измерения сетка и курсор возвращаются до передачи хранилищ другому миру.

## Основные данные ядра

| Поля                              | Содержание                                                                                                                   |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `generator`                       | идентификатор, версия, сид, preset                                                                                           |
| `gameMode`, `journey`             | режим `survival/creative/lab` и выполненные первые шаги                                                                      |
| `dimension`                       | активное измерение `overworld/nether/end`                                                                                    |
| `dimensions`                      | `{ dimension, state }` с хранилищами неактивных измерений                                                                    |
| `tick`, `time`, `scheduler`       | такт, время 0–23 999, очередь событий                                                                                        |
| `spawn`, `player`, `look`         | исходная точка Верхнего мира, позиция/скорость/флаги игрока, обзор                                                           |
| `inventory`, `cursor`             | 41 слот: хотбар 0–8, рюкзак 9–35, броня 36–39, левая рука 40                                                                 |
| `survival`                        | здоровье, поглощение, еда/насыщение/истощение, воздух, опыт, эффекты, сложность, смерть и точка кровати в Верхнем мире       |
| `containers`                      | сундуки, печи, воронки, раздатчики/выбрасыватели; у печей burn/cook/xp/perItem                                               |
| `items`, `mobs`, `arrows`, `orbs` | сериализуемые поля соответствующих сущностей                                                                                 |
| `bosses`                          | положения, здоровье и фазы боссов, кристаллы, `dragonEncountered`, `dragonDefeated`                                          |
| `blocks`                          | очереди жидкостей, огня, фитилей, падающих блоков и редстоуна                                                                |
| `brewing`                         | ингредиент, бутылки, порошок, топливо и прогресс; старые tuple-слоты и объектные слоты нормализуются                         |
| `carts`                           | вид, дробные x/y/z и vx/vz; грузовой инвентарь и посадка не сериализуются, потому что такого контейнера у текущей модели нет |
| `enchantments`                    | только пустой legacy-контейнер совместимости в новых снимках                                                                 |
| `editCount`, `overrides`          | счётчик изменений и `[x,y,z,blockKey,dimension?]`; без измерения означает Верхний мир                                        |

Координаты блоков ограничены диапазоном хранения `y = 0…255`. Пространственные позиции сущностей — отдельный контракт: отрицательная высота разрешена, в том числе ниже −64, чтобы падение и смерть в пустоте не делали файл несохраняемым. Все координаты конечны и ограничены. Числа, размеры коллекций, ключи блоков/предметов и дубликаты проверяются кодеком; размер входного файла ограничен 16 МиБ.

Необязательное седьмое поле существа — объект с короткими ключами: `g` возраст (отрицательный у детёныша), `v` окраска овцы или профессия жителя (0 фермер, 1 библиотекарь, 2 священник, 3 кузнец, 4 мясник), `s` = 1 у остриженной овцы, `c` перерыв между размножениями, `h` дом жителя `[x, y, z]` (центр его деревни), `u` счётчики сделок жителя со времени последнего пополнения (целые 0–1000, не больше 32 чисел). Ключи `h` и `u` появились в 0.12.0, формат остался шестым. Поплавок удочки не сохраняется, как и в 1.12.

Таймеры внутренней реализации не обещаются как побитовое возобновление всей симуляции: например, у обычного существа сохраняются вид, координаты, здоровье и поворот, но не полная память ИИ; снаряды иссушителя и промежуточные таймеры фаз босса не входят в текущую схему. Неактивные измерения не симулируются в фоне.

## Клиент и обнаружение изменений

`client.settings`: `radius` 2–5, `fov` 55–100, `sensitivity` 0.3–2.5. Громкость и настройки доступности — общие для приложения, отдельно в localStorage с безопасным fallback для opaque origin; они не меняют игровой файл мира.

Worker вычисляет отпечаток сохраняемых доменов не чаще двух раз в секунду при обычном ходе и немедленно на значимой команде/захвате. Журналы блоков имеют собственные ревизии. Неподвижный мир не меняется в индикаторе только из-за каждого нового такта; ход часов учитывается минутными интервалами, а явная смена времени — сразу. Ручное сохранение всё равно захватывает **точные текущие** tick/time.

Ответ захвата — билет `{ core, stamp }`. Координатор сохраняет `core` и подтверждает `stamp` вместе с захваченными настройками клиента. Использовать «самое последнее» состояние браузера после завершения транзакции нельзя: это скрыло бы ещё не записанные изменения.

Тяжёлые проекции контейнеров передаются клиенту реже; это не источник истины для сохранения. Сохранение всегда получает отдельный актуальный checkpoint из Worker.

## Восстановление и отказ

- Повреждена основная копия: загрузить предыдущую проверенную, показать предупреждение; не удалять повреждённую запись без следующего подтверждённого сохранения.
- Изменена ревизия в другой вкладке: конфликт, а не молчаливая перезапись.
- Не хватает места/транзакция прервана: старая запись остаётся, индикатор ошибки, доступен экспорт.
- IndexedDB запрещён: честный временный режим в памяти вкладки; экспорт обязателен для переноса и сохранения после закрытия.
- Дракон уже побеждён: не начинать новый бой при входе. Старые признаки победы дополнительно восстанавливаются из яйца и выходного портала в журнале Края. Повторный бой — отдельный игровой ритуал.
